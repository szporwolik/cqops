# CQOps ユーザーマニュアル

CQOps は、自宅、移動運用、クラブ局、気軽なコンテスト参加に向いた、キーボード操作のアマチュア無線ログソフトです。QSO は最初にパソコンへ保存され、インターネットサービスの利用は任意です。まず手動での記録から始め、必要に応じて無線機制御やオンラインサービスを追加してください。

このマニュアルのメニュー名と項目名は英語表示に合わせています。ショートカットは画面によって異なります。画面下のヘルプバーまたは **?** で確認してください。

## インストール

[リリースページ](https://github.com/szporwolik/cqops/releases)から CQOps を入手します。ターミナルは最低 75 × 24 文字、快適な操作には 80 × 43 文字以上を確保してください。

| OS | インストール方法 |
|---|---|
| Windows | `cqops-setup.exe` を使うか、インストール不要の `cqops-windows-portable.zip` を展開します。Windows Terminal を推奨します。 |
| Debian、Ubuntu、Linux Mint、Pop!_OS | 対応する `.deb` を選びます。一般的な Intel/AMD PC は `amd64`、64 ビット ARM は `arm64`、32 ビット Raspberry Pi OS は `armhf` です。パッケージインストーラーで開きます。 |
| Fedora、RHEL、Rocky、AlmaLinux | 下記のリポジトリ用コマンドを使います。 |
| Arch、Manjaro、CachyOS | `paru -S cqops-bin` または `yay -S cqops-bin` で AUR パッケージを入れます。 |
| その他の Linux | CPU に合う Linux 用 `.tar.gz` をリリースページから入手し、展開します。 |
| macOS | Apple Silicon は `cqops-darwin-arm64`、Intel は `cqops-darwin-amd64` を入手し、下記のコマンドを使います。 |

Debian 系では、リポジトリからのインストールも可能です。

```bash
curl -1sLf 'https://dl.cloudsmith.io/public/szporwolik/cqops/setup.deb.sh' | sudo -E bash
sudo apt update
sudo apt install cqops
```

Fedora 系の場合：

```bash
curl -1sLf 'https://dl.cloudsmith.io/public/szporwolik/cqops/setup.rpm.sh' | sudo -E bash
sudo dnf install cqops
```

macOS ではダウンロード先のフォルダーで次を実行します。`FILE` は実際のファイル名に置き換えてください。

```bash
chmod +x FILE
sudo mv FILE /usr/local/bin/cqops
```

`cqops` または展開したポータブル版を起動します。`cqops --offline` はオフライン起動、`cqops --version` はバージョン表示、`cqops --help` は起動オプションの表示です。更新前にログをエクスポートしてください。

<a id="setup"></a>

## 初期設定

初回ウィザードでログブック名、局のコールサイン、Maidenhead グリッドロケーター、大陸を設定します。**局のコールサイン**は送信時に使うもの、**オペレータープロファイル**は操作する人を示します。

**Ctrl+A** で任意の局リファレンスと CQ/ITU ゾーンを表示できます。自局の SOTA/POTA/WWFF リファレンスは局／ログブック設定に入力します。QSO フォームのリファレンスは相手局のものです。IARU リージョンは後で **F9 → Logbooks** から設定します。

名前、アンテナ、出力を指定して無線機プロファイルを作ります。周波数とモードを手入力する場合は **None**、制御する場合は **flrig** または **Hamlib** を選びます。任意の接続は、基本的なログ入力を確認してから追加してください。

**Tab / Shift+Tab** で項目を移動し、**Space** で選択肢を変更、**Save & Next** で次へ進みます。**Esc** は戻る、**F10** は終了です。最後に内容を確認して保存します。CQOps はパソコンのタイムゾーンを検出しますが、QSO の日時は UTC です。運用前にパソコンの時計を確認してください。

<a id="first-qso"></a>

## 最初の QSO

1. **F1** を押し、ログブック、局コールサイン、オペレーター、無線機、コンテストを確認します。
2. 相手局のコールサインを入力します。検索を設定済みなら **Ins** で照会できます。
3. UTC 日時、MHz 単位の周波数、バンド、モード、送受信レポートを確認します。
4. 必要に応じて名前、QTH、ロケーター、リファレンス、コメントを追加します。
5. **Enter** で保存します。Recent QSOs に交信が表示されます。

**DUPE!** が確認を求めた場合、もう一度 **Enter** で保存、**Esc** で確認を取り消します。重複警告は内容を確認するためのもので、必ず破棄すべきという意味ではありません。

## 画面とステータス

| キー | 画面 | 用途 |
|---|---|---|
| F1 | QSO | 交信の入力、最近の QSO |
| F2 | Partner | 相手局情報、地図、統計、写真 |
| F3 | APRS | 近隣局 |
| F4 | DX Cluster | スポットと絞り込み |
| F5 | PSK Reporter | デジタルモードの受信レポート |
| F6 | References | SOTA、POTA、WWFF、IOTA の検索 |
| F7 | Band Plan | 周波数と運用プリセット |
| F8 | Logbook | 編集、インポート、エクスポート、同期 |
| F9 | Configuration | 局とサービスの設定 |
| F10 | Quit | CQOps の終了 |

上部には現在の局設定、ローカル時刻（**L**）、UTC（**Z**）が表示されます。接続表示は通常、白が有効、黄が無効／接続中／待機、赤がエラーです。WSJT は送信中に強調表示されます。**WL!** は未対応の旧 Wavelog キーを示します。

<a id="logging"></a>

## 日常のログ入力

**Tab / Shift+Tab** で項目を移動し、**PgUp / PgDn** でバンド、モード、サブモードを切り替えます。**Shift+Backspace** は現在の項目、**Del** はフォーム全体を消去します。スプリット運用では **Freq RX** を確認してください。

**Keep** は保存後もコメントを残します。**Retain** はフォーム全体を残すので、次の保存前にコールサイン、時刻、レポート、リファレンスを確認してください。コンテスト交換情報はコンテスト有効時だけ表示されます。その他の特別なグループ情報には **SIG / SIG Info** を使います。

双方のロケーターがわかると距離と方位が表示されます。コールブックの所在地は現在の移動先ではなく自宅の場合があるので確認してください。新しいコールサイン、新しい DXCC、重複の表示も判断の補助になります。

**F6** は名前や識別番号でリファレンスを検索し、相手局の欄に入力できます。**F7** はバンドプランを表示し、接続した無線機を同調できます。掲載情報は運用の補助であり送信許可ではありません。免許の範囲と地域のバンドプランを確認してください。

共通のお気に入り 3 枠に周波数、モード、バンドを保存できます。

| 枠 | 呼び出し | 現在値の保存 |
|---|---|---|
| 1 | Alt+Ins | Alt+Shift+Ins |
| 2 | Alt+Home | Alt+Shift+Home |
| 3 | Alt+PgUp | Alt+Shift+PgUp |

<a id="profiles"></a>

## 局のプロファイル

ログブック、オペレーター、無線機、コンテストは **F9** の各メニューで作成し、**Ins** で追加します。QSO 画面では次のように切り替えます。

| キー | 切り替える対象 |
|---|---|
| Ctrl+L | ログブック |
| Ctrl+O | オペレーター |
| Ctrl+R | 無線機 |
| Ctrl+C | コンテスト |

ログブックごとに局情報と Wavelog/APRS 設定を保持します。オペレーターのコールサインは ADIF `OPERATOR` に記録されます。無線機プロファイルは機材、出力、無線機／ローテーター制御、WSJT-X 設定を保持します。特に自動デジタルログ中は、切り替えるたびにステータスバーを確認してください。

ほかの **F9** メニューでは表示、単位、タイムゾーン、コールブック、連携機能、通知音を設定します。

<a id="logbook"></a>

## ログブックとバックアップ

**F8** で QSO を選び、**Enter** または **e** で編集します。**Enter** で保存し、確認します。**Delete** は選択した交信の削除です。一括変更前にはバックアップを作成してください。**Ctrl+P** は全 QSO を削除する操作で、検索ではありません。

| F8 のキー | 操作 |
|---|---|
| Ctrl+I | ADIF を取り込み、記録を検証して重複を除外 |
| Ctrl+E | 全交信またはコンテストで絞った交信を出力 |
| Ctrl+W | 未送信の交信を Wavelog に送信 |
| Alt+W | Wavelog から取得 |

取り込み結果と出力対象を確認してください。取り込んだ交信も後から Wavelog に送信される場合があります。CQOps は ADIF 3.1.7 に対応し、コンテスト ID と交換情報を保持します。ログブックごとに、できれば別の機器へバックアップしてください。ADIF は交信のバックアップであり、すべての設定や認証情報を含むものではありません。

設定ファイルは Linux/macOS では `~/.config/cqops/config.yaml`、Windows では `%APPDATA%\cqops\config.yaml` です。認証情報は別の `secrets.enc` に保存され、別のパソコンへ移す際は再入力が必要です。トラブル対処の最初に設定ファイルを削除しないでください。

<a id="radio"></a>

## 無線機とデジタルモード

### 無線機制御

**F9 → Rigs** で flrig または Hamlib を選び、接続設定を合わせます。先に flrig または `rigctld` を起動します。flrig の通常の接続先は `localhost:12345` です。周波数、モード、スプリット、出力の取得可否は無線機によります。**None** では手動入力します。

### WSJT-X

WSJT-X 2.6 以降を使います。**Settings → Reporting → UDP Server** と、CQOps の使用中の無線機プロファイルの UDP 設定を合わせます。完了したテスト QSO を WSJT-X に記録し、CQOps に表示されることを確認してください。

受信した QSO は現在のログブックとコンテストに入り、重複は除外されます。運用前にオペレーターと WSJT 表示を確認します。オペレーターが異なると警告されます。設定済みなら Wavelog への送信も可能です。Mode/Submode を適切に選んでください。FT8 は FT8、FT4/FT2 は MFSK と対応するサブモードで出力されます。

### ローテーター制御

Hamlib `rotctld` による制御は実験的機能です。使用前に方向と機械的限界を確認し、安全に停止できる手段を用意してください。誤設定はアンテナ、ローテーター、給電線を破損するおそれがあります。

| キー | 操作 |
|---|---|
| Alt+, / Alt+. | 方位角 −5° / +5° |
| Alt+' / Alt+; | 仰角 −5° / +5° |
| Alt+\ | 計算された方位へ向ける |
| Alt+/ | 動作を停止 |

<a id="online"></a>

## オンラインサービス

### コールブック

**F9 → Callbook** でサービスと優先順位を設定し、QSO フォームで **Ins** を押します。有効なサービスが順番に照会されます。基本コールサインでの再検索では移動用のプレフィックス／サフィックスを除く場合があります。取得した所在地を確認してください。

| サービス | 利用条件 |
|---|---|
| QRZ.com | XML 契約と認証情報 |
| HamQTH | 無料アカウント |
| QRZ.RU | Web サイトとは別の API ログイン |
| Callook.info | 米国コールサイン、アカウント不要 |

**F2** で相手局情報を表示します。写真はサービスとターミナルに依存します。General 内の実験的な **Kitty Graphics** には Kitty、Ghostty、WezTerm などの対応ターミナルが必要です。

### Wavelog

ログブックごとに URL、API v2 トークン（`wl2_…`）、局プロファイルを設定します。旧 v1 キーは使えません。Wavelog の局を選ぶと自局情報が入力される場合があります。保存前にコールサイン、ロケーター、リファレンスを確認してください。

QSO はまずローカルに保存されます。失敗した送信は **F8 → Ctrl+W** で再試行し、**Alt+W** で交信を取得します。リンクされた QSO を編集する際、Wavelog の内容で更新される場合があります。オンラインでの編集・削除はリモートの記録にも反映されます。特にオフラインでは確認文を読み、ローカルのみの変更が Wavelog に届いたと思い込まないでください。

### DX Cluster と伝搬状況

Integrations で DX Cluster を設定し、**F4** を開きます。**b / c / m / t** はバンド、投稿局の大陸、モード、経過時間で絞り込み、**Backspace** は解除します。**Enter** は QSO フォームを入力し、接続中の無線機を同調して F1 に戻ります。**Space** はクラスター画面のまま同調します。

F1 の **Ctrl+S** はスポット送信画面を開き、**Ctrl+P** は最も近い表示スポットからコールサインを取得します。送信前に確認してください。**F5** の PSK Reporter は受信報告であり、現在の伝搬を保証するものではありません。Solar は HamQSL の情報を表示しますが、キャッシュは古い場合があります。

<a id="position"></a>

## GPS と APRS

### GPS

Integrations でシリアル GPS または GPSD を設定します。局／ログブック設定の **Grid from GPS** を有効にすると、QSO、方位、APRS、ダッシュボードでそのロケーターを使います。GPS は赤がエラー、黄が未測位、白が測位済みです。運用前に表示を確認してください。6、8、10 文字を選べますが、文字数が多くても受信機の測位精度が上がるわけではありません。

### APRS

| サービス | 接続 |
|---|---|
| APRS-IS | インターネット上の APRS サーバー |
| KISS | シリアル接続のハードウェア TNC と無線機 |
| KISS Server | Dire Wolf などの TCP TNC。ローカルでも使用可能 |

**F9 → Integrations → APRS** で選択します。コールサイン／SSID、シンボル、コメント、範囲、送信間隔は **F9 → Logbooks → [active logbook] → APRS** で設定します。送信する場合だけ **APRS TX** と **Send beacons** を有効にします。受信のみでは **APRS-RX** と表示されます。位置ビーコンは所在地を公開するため、位置と公開範囲を確認してください。

自動ビーコンの間隔は最短 5 分です。**F3** に最近受信した局が表示されます。矢印で選択、**Enter** で QSO 入力、**d / t / s** で距離／経過時間／種類の絞り込み、**Backspace** で解除、**b** で設定済みのビーコンを即時送信します。GPS 位置の送信には **Grid from GPS** と有効な測位結果が必要です。

<a id="portable"></a>

## 移動運用

出発前に移動用ログブックを選び、コールサイン、ロケーター、アクティベーションのリファレンス、無線機、アンテナ、出力を確認します。構成全体を試し、CQOps をオンラインで起動してリファレンスとプレフィックスのデータを更新してください。**F6** で必要なリファレンスが見つかることを確認し、バックアップを出力します。

インターネットがなくてもローカル記録は使えます。`cqops --offline` はネットワーク機能をスキップするため、オンライン照会や同期に頼らないでください。ローカルネットワーク機器も、出発前に実際の起動モードで試してください。キャッシュ情報は古い場合があります。

運用後に QSO 件数とリファレンスを確認し、ADIF を出力してバックアップを保管します。Wavelog 利用時は未送信分を送ります。各アワードの提出形式を確認し、必要なら変換してください。

<a id="contests"></a>

## コンテスト

CQOps は気軽なコンテスト記録、交換情報、連番、QSO レートに対応しますが、完全な採点・提出システムではありません。本格的な運用には専用ソフトを使ってください。

**F9 → Contests** で **Ins** を押し、名称、日付、ADIF コンテスト ID、開始番号、送受信交換情報のテンプレートを設定します。

| 記号 | 値 |
|---|---|
| `@rst` | 送信または受信レポート |
| `@serial` | 連番 |
| `@cqz` / `@mycqz` | 相手局／自局の CQ ゾーン |
| `@itu` / `@myitu` | 相手局／自局の ITU ゾーン |
| `@grid` / `@mygrid` | 相手局／自局のロケーター |

**F1** では **Ctrl+C** でコンテストを切り替えます。送信前に交換情報と次の番号を確認してください。ステータスバーに件数、次の番号、時間が表示され、広い画面では追加のレート統計も表示されます。終了後はコンテストなしの運用に戻します。

出力時は **F8** で **Ctrl+C** により対象コンテストを絞り込み、**Ctrl+E** で選択内容を確認します。出力は ADIF であり Cabrillo ではありません。主催者の形式・提出規定に従ってください。

<a id="dashboard"></a>

## CQOps Live

**F9 → Integrations → HTTP Server** を有効にし、**Ctrl+S** で保存します。CQOps のパソコンで `http://localhost:8073` を開きます。

標準の `0.0.0.0` は、ファイアウォールが許可すれば LAN 内からアクセスできます。別の機器では CQOps パソコンの IP とポート `8073` を指定します。`127.0.0.1` にするとそのパソコンだけに限定できます。信頼できるネットワークで使い、ポートをインターネットへ転送しないでください。

現在の相手局、QSO 地図、最近の交信、レート、オペレーター、APRS、利用可能な伝搬／天気情報が自動更新されます。オフラインではインターネット依存のレイヤーは利用できない場合があります。Header 1、Header 2、Logo URL、Event Start でイベント表示を調整します。開始日は表示する統計と QSO 一覧の対象を絞ります。

## キーボード操作一覧

| 画面 | キー | 操作 |

| QSO | Enter / Ins | 保存／照会 |
| QSO | Shift+Backspace / Del | 項目／フォームを消去 |
| QSO | Ctrl+L / Ctrl+O / Ctrl+R / Ctrl+C | ログ／オペレーター／無線機／コンテストの切り替え |

<a id="help"></a>

## トラブル対処と問い合わせ

| 問題 | 最初に確認すること |
|---|---|
| 起動しない／表示が欠ける | ターミナルの大きさ、Windows Terminal、`cqops --offline` での起動 |
| 無線機につながらない | プロファイル、flrig/rigctld の起動、機種、シリアルポート、速度、ホスト／ポート、他ソフトのポート占有 |
| WSJT-X の QSO がない | UDP の一致、WSJT 表示、WSJT-X で実際に保存済みか、現在のログブック |
| Wavelog エラー | URL、`wl2_` トークン、局プロファイル、ネット接続。ローカル QSO は残る |
| GPS 位置がない | ポート／速度または GPSD アドレス、空の見通し、測位結果、Grid from GPS |
| APRS ビーコンが出ない | ログブック、APRS TX と Send beacons、コールサイン／SSID、TNC／無線機またはネット接続 |
| ダッシュボードが開けない | サーバー有効化、IP／ポート、ファイアウォール。localhost はブラウザーが動く機器を指す |

設定の問題は、ファイルを変更する前に **F9** で確認します。認証情報の保存に問題がある場合やパソコンを変更した場合は、認証情報を再入力してください。

必要なら **F9 → General → Debug** を有効にし、安全に問題を再現して該当する診断ログを取得します。その後、デバッグを無効に戻してください。

| OS | 診断ログ |
|---|---|
| Linux | `~/.local/share/cqops/logs/` |
| macOS | `~/Library/Application Support/cqops/logs/` |
| Windows | `%APPDATA%\cqops\logs\` |

[GitHub Issues](https://github.com/szporwolik/cqops/issues) に、CQOps のバージョン、OS、ターミナル、再現手順、必要なログを添えて報告してください。共有前にパスワード、API トークン、個人情報を削除してください。
